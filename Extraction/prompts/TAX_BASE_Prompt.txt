0B.2  GARBLED / ROTATED TEXT HANDLING
  Some pages are physically embedded in landscape orientation (rotated 90° or 270°).
  When extracted as plain text, these pages produce one of the following garbled patterns:

  PATTERN 1 — single-character-per-line stream: characters appear one per line down
    the left margin (e.g. "F / i / s / c / a / l"). Collapse all single characters
    top-to-bottom into words/phrases before evaluating.

  PATTERN 2 — reversed or mirrored word stream: words or numbers appear in reversed
    reading order or as one long unseparated string. Re-assemble before evaluating.

  PATTERN 3 — numeric column collapse: all values that should occupy separate year
    columns appear run together on one line (e.g. "63599222 68171229 73503171").
    Re-space them by matching against the number of year columns the schedule is
    known to have, using value magnitude as a guide:
      • Assessed/EAV values: 8–12 digits (hundreds of millions to trillions).
      • Millage rates: 1–2 digits with exactly 3 decimal places (e.g. 7.107).
      • Levy amounts: 6–9 digits (hundreds of thousands to billions).
      • Collection percentages: 2 digits with 2 decimal places (e.g. 94.10).

  MANDATORY RULES FOR ALL ROTATED PAGES:
  (a) NEVER skip or discard a rotated page without first reconstructing its content
      using the pattern rules above.
  (b) After reconstruction, apply ALL normal schedule-matching rules (Section B,
      §0B.3, §0B.4) to the reconstructed text exactly as if it were a normal page.
  (c) A rotated page that, after reconstruction, contains a target schedule title OR
      matches the column/row patterns of a target schedule MUST be processed and its
      values extracted — rotation alone is NEVER a reason to emit "-".
  (d) When extracting numeric values from a PATTERN 3 page, assign each reconstructed
      number to its year column by position count and magnitude cross-check. If
      position count and magnitude conflict, re-read the page before accepting.
  (e) Apply §0B.4(b) nearest-position column alignment AFTER reconstruction, never
      before.
  (f) A hyphen/dash INSIDE a de-garbled text label is part of the label — never treat
      it as a missing-value marker or truncate the label there.
  (g) Record the physical page number of every rotated page used as a source in
      Page No, exactly as for any other page.

0B.3  MULTI-PAGE / CONTINUATION-SCHEDULE DETECTION
  Statistical-section trend schedules (the three target schedules in Section B) frequently
  span two or more physical pages. Recognise BOTH of the following continuation patterns and
  INCLUDE every such page as part of the same schedule (do not stop at the first page):
    - TYPE 1 (column overflow): the continuation page has no repeated title — it begins
      directly with additional year-columns and their data rows (e.g., the first page
      shows FY2025–FY2021 and the next page shows FY2020–FY2016 for the same schedule).
    - TYPE 2 (row overflow / "(Continued)"): the continuation page repeats the schedule
      title with "(Continued)" or resumes mid-table with the same row labels.
  STOP including pages for a given schedule only when you reach: a new, unrelated schedule
  title; a section divider or blank page; or the start of the next Statistical Section
  category (e.g., moving from "Revenue Capacity Information" schedules into "Debt Capacity
  Information" schedules). Never stop at the first page of a continuation schedule merely
  because the first page appeared complete — always check the following page(s) for
  overflow columns or rows belonging to the same schedule.
0B.4  VALUE-TOKEN INTEGRITY (dash normalisation, column alignment, digit-drop repair)
  Apply the following to every numeric cell you extract from the three target schedules:
  (a) DASH-GLYPH NORMALISATION: treat every dash variant (-, hyphen, en dash, em dash,
      minus sign, or any similar glyph) as one dash token "-"; ignore "$" and thousands
      commas when reading a value. A printed dash or a genuinely blank cell BOTH map to the
      literal "-" in output. Never treat a standalone dash as a negative sign; a dash glued
      directly to a digit with no space (e.g., "-1,234") IS a negative sign in that case.
      Fix obviously broken parentheses such as "5,232)" → "(5,232)"; never convert a
      parenthesised negative into a dash or vice versa.
  (b) COLUMN / YEAR ALIGNMENT (nearest-position, never sequential packing): before recording
      any row's values, first establish the FULL set of year-column headers printed for that
      schedule (including any header fragments split across two lines, and including columns
      that continue onto a subsequent physical page per 0B.3). Assign each printed number to
      the year column it is physically aligned under (nearest column position), NOT simply
      to "the next value you see." If a year column is genuinely blank for a given row, its
      slot stays "-" — do NOT shift subsequent values left to fill the gap. This is
      especially important where a schedule's data has an irregular number of populated
      columns per row (e.g., a component added mid-decade).
  (c) DIGIT-DROP DETECTION (sanity check on run-level trend values; run on every year
      value you are about to record for Rows 1, 3, 5 [Assessed Value, Full Value, Levy]):
      compare the candidate value against the immediately adjacent year(s) already
      extracted for the SAME row. If the candidate is less than 20% or more than 500% of
      the adjacent year's value with no plausible printed explanation (e.g., no footnote
      describing reassessment, annexation, or a one-time revaluation), treat the token as
      SUSPECT. Re-read the source page/column position carefully to check for a
      dropped or duplicated leading/trailing digit before accepting the value. If, after
      re-reading, the printed figure genuinely is what it is, accept it as printed — never
      alter a real printed value merely to force smoothness. Only correct a value when you
      can identify an actual mis-read digit against the source page; never fabricate a
      "corrected" number that is not printed anywhere in the PDF.
  (d) NEVER let a token-count mismatch (fewer printed numbers than year columns) cause you
      to compress or left-pack the remaining values into the wrong columns. Missing trailing
      or interior columns must be recorded as "-", not silently dropped, which would shift
      every later column one slot to the left.
