G3.4  MANDATORY: DIGIT-DROP DETECTION & REPAIR (CRITICAL — RUN ON EVERY CP ROW)
===============================================================================
A digit-drop occurs when a PDF extractor silently drops a character from a number
(e.g., "16,760,001" → "1,676,001").

STEP 1 — PRE-ACCEPTANCE SANITY BOUND:
  For every token T on a CP row assigned to column C:
    floor_estimate = 0.80 × sum(all DP values seen above in column C)
    ceil_estimate  = 1.20 × sum(all DP values seen above in column C)
    If T < floor_estimate OR T > ceil_estimate: Mark T as SUSPECT → STEP 2.
    Else: accept T as-is.

STEP 2 — DIGIT-DROP REPAIR ATTEMPT (SUSPECT tokens only):
  Insert a single digit (0–9) at every character position in T.
    One candidate matches sum(DP[C]) within $1 → ACCEPT and replace T.
    Zero or multiple candidates match → keep original T, log it.

STEP 3 — MANDATORY TOTAL RECONCILIATION:
  After all section rows assigned, for each column C: verify sum(DP[C]) ≈ CP[C].
  If mismatch > $1 AND STEP 2 not yet applied → re-run STEP 2.

STEP 4 — EXTRACTION WARNING (if repair fails):
  Add to Metadata: "Extraction Warnings": ["Digit-drop suspected: Col=<ColName>,
  Row=<RowLabel>, raw=<T>, expected=<sum(DP[C])>"]
  Still output original raw token T. Never silently substitute an unverified guess.

ABSOLUTE RULES:

  Never skip this check even if token count = N.
  Repair is arithmetic-confirmed only; never guess.
