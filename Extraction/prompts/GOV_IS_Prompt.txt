===============================================================================

DASH-ONLY ROW RULE: A row whose ONLY value tokens are dashes "-" (no numeric

TYPE A (Group Header): No numeric values (blank or dash-only).

TYPE B (Child Data Row): Has numeric value(s) AND indent > stack top's indent.

TYPE C (Sibling/Ancestor/Total): Has numeric value(s) AND indent <= stack top's

STACK RULES:
  SIBLING RULE: Processing sibling at level N does NOT pop parent at N-1.
  SAME-LEVEL POP: Data row at indent == stack_top.indent -> pop stack_top first.
  NO SEMANTIC OVERRIDES: Never pop based on label words. Only indent triggers pops.

G. VALUE EXTRACTION + COLUMN ASSIGNMENT (ANTI-SHIFT GUARANTEE)
===============================================================================

G1) EXTRACT VALUES

DASH GLYPH NORMALIZATION (CRITICAL -- RUN BEFORE ALL OTHER STEPS):
Treat ALL of the following as equivalent dash cell tokens:
  U+002D  -   (hyphen-minus)
  U+2010  -   (hyphen)
  U+2013  --  (en dash)
  U+2014  --- (em dash)
  U+2012      (figure dash)
  U+FE58      (small em dash)
When a PDF extractor drops or skips one of these characters, it creates
a MISSING CELL, not a missing value. Treat it as "-" and preserve it
as a real column slot -- do NOT collapse surrounding tokens to fill the gap.

BLANK CELL vs DROPPED DASH DISTINCTION (CRITICAL):
  TYPE 1 -- PRINTED DASH: treat as "-" token.
  TYPE 2 -- EMPTY CELL (no character): still a real column slot -> "-".
  It is NOT a signal to pack surrounding tokens left.

TOKEN COUNT vs N:
  If token count = N: assign left-to-right.
  If token count < N: use POSITION-FIRST rules (G2-MAP) to determine placement.
    Never assume the gap is at the right end.
    Never pack tokens into the leftmost slots.

DASH TOKEN PRESERVATION (CRITICAL):
  Treat any dash glyph as a real cell token.
  Never collapse "--" into one "-" token.
  Never drop dash tokens during extraction.

DASH-NEGATIVE FUSION PREVENTION (CRITICAL):
  Standalone spaced dash = independent cell token, NEVER negative sign.
  Dash + whitespace + value = TWO tokens.
  Dash immediately adjacent to value (no gap) = negative sign.

ZERO-VALUE ROW PRESERVATION (CRITICAL):
  Row with ZERO numeric tokens = all-dash row. Emit with "-" in every column.
  Never skip it, never merge with adjacent rows.

Valid cell tokens: numeric with commas | parenthesized negatives | dash cell.
Ignore "$" signs.
Fix broken parentheses: "5,232)" -> "(5,232)", "(5,232" -> "(5,232)".
Preserve parentheses exactly as shown in the PDF.
OUTPUT VALUES AS STRINGS -- "1,234,567" not 1234567. Never convert to integers/floats.

NO ADDEND SWAP RULE -- CRITICAL:
  First token -> Col1, second -> Col2. Strict left-to-right.
  Never swap even if swapping satisfies Total.

ABSOLUTE ADDEND ORDER LOCK -- CRITICAL:
  If token count = N and SUM = sum(addends): DO NOT reorder.

G2) COLUMN ASSIGNMENT -- POSITION-FIRST (CRITICAL)

INDEPENDENT COLUMN ABSOLUTE TOKEN-ORDER LOCK:
  Columns RIGHT of SUM are INDEPENDENT.
  Assign STRICTLY left-to-right. NEVER swap '-' and numeric between adjacent.
  If token count = N, output exactly as-is.

ARITHMETIC SELF-CHECK (run after all rows assigned):
  Sum DP values per column, compare to CP Total. Mismatch = left-shift error.

The single most important rule: assign tokens using their horizontal PDF
position, not by packing them left-to-right sequentially.

TRAILING INDEPENDENT COLUMN DASH-DROP RECOVERY (CRITICAL):
  When token count < N: map each token to column by x0 position,
  identify empty slots, insert "-" at each gap, verify with arithmetic.

COLUMN x-RANGE ESTABLISHMENT (ONE-TIME):
  From header block, record x0/x1 per column. Lock for entire statement.

G2-MAP) VALUE-TO-COLUMN MAPPING -- NEAREST-POSITION INITIALIZATION (CRITICAL)

THIS OVERRIDES ALL OTHER COLUMN ASSIGNMENT LOGIC.

  STEP 1 -- Initialize all N columns as "-".
  STEP 2 -- Establish ColCenter[1..N] from header + first 5 data rows. FIXED.
  STEP 3 -- For each token, assign to nearest ColCenter. If collision, keep closer.
  STEP 4 -- Output. Unassigned slots stay "-". Do NOT shift/pack/rearrange.

SEQUENTIAL PACKING IS FORBIDDEN:
  X WRONG: "3 tokens for 5 columns -> Col1, Col2, Col3"
  V RIGHT: "3 tokens -> check horizontal position -> assign by position -> gaps = '-'"

G2-SPLIT) TWO-PAGE TABLE MERGING -- Y-COORDINATE ROW CLUSTERING (y_tol <= 3.5)

SPARSE COLUMN ANTI-SHIFT (CRITICAL):
  Token count < N: identify which columns blank by horizontal position.
  Do NOT pack left-to-right. Insert "-" at each blank column position.

CLUSTERING RULE: Sort words by (top, x0). Group using running avg top (tol 3.5pt).
STEP 1 -- Cluster Page 1 into rows (all-dash rows are real rows).
STEP 2 -- Cluster Page 2 into value groups.
STEP 2B -- Row count integrity: if P2 fewer groups, insert synthetic all-dash groups.
STEP 3 -- Match P2 groups to P1 rows by avg_top (minimize distance).
STEP 4 -- Row count check. Unmatched P1 rows get "-" for remaining columns.

G2A) ELIMINATION ROW DETECTION -- RUNS BEFORE ANY REPAIR

PRE-CHECK: If token count < N and one positive P + one negative where |P|=|N|:
  missing token = "-". SUM must be "-". Insert "-" at gap.
STEP 1 -- Assign left-to-right.
STEP 2 -- Confirm elimination: addends sum = 0.
STEP 3 -- SUM column must be "-". If not, move value to rightmost empty addend.
STEP 4 -- Output. Skip G3. Col[S] always "-".

G3) ALIGNMENT REPAIR USING SUM LOGIC

Run ONLY if: token count != N, OR SUM != sum(addends), OR dash dropped, OR wrong column.
DO NOT run if: token count = N AND SUM = sum(addends) AND left-to-right order correct.

G3.0 CONTRA-ADDEND REPAIR: If SUM has Z, addend has Y, Y+Z=0 -> move Z to addend, SUM="-".
G3.1 ZERO-SUM SAFEGUARD: If addends sum=0, SUM must be "-".
G3.2 NORMAL SUM VERIFICATION: Verify/repair SUM = sum(addends).
G3.3 MANDATORY TOTAL RECONCILIATION: After section, sum(DP) must equal CP Total per column.
     If mismatch: identify cause, re-examine, correct.

G4) No duplication: each PDF value in only one column.
G5) DPG rows: all values = null (not "-").
